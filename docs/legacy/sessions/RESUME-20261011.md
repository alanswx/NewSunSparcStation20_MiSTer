## Gotchas learned this session

- A cached device mapping looks like a frozen device: a value read twice
  through the kernel's VA stays the same while the physical read moves.
  The MMU probe (`pcdump -A 3,<va>|0x400`) shows the PTE's C bit.
- OpenBIOS's `bug` handler (an unexpected trap, ET=0) turns the MMU off
  and prints tt, PC and nPC as one run of hex digits on ttya
  ("0000000200089e7000089e74" = tt 2 at 0x89e70); pcdump then finds CPU 0
  looping at a low physical address (0x84b0).
- Main's file lists hide `boot*.rom` (file_io.cpp), so `boot0.rom` cannot be
  picked in the Boot PROM list: releases ship OpenBIOS also as
  `openbios.rom`. The core's file browsers reopen on the file chosen last;
  the OSD hides itself after a few idle seconds.
- A back-end CUE test (config-file writes, `load_core`) once left Main not
  reading /dev/MiSTer_cmd; the same CUE through the OSD worked.
- A Boot PROM chosen in the OSD (config/SunSparcStation.f0) overrides
  boot.rom: the board scripts forget it at every core start
  (`KEEP_PROM=1` keeps it; `mount.sh --prom` sets it).
- `SETOPT_FORCE="name=value"` holds an OSD option through a whole test run.
- Main: a branch created from `origin/master` tracks master; after a push,
  add commits rather than amending (the user's push was rejected once).
- `tools/mknvram.py --help` writes an NVRAM image named `--help`.
