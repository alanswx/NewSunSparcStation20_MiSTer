## Where things stand

- **Session 12, N1 (NeXTSTEP 3.3 for SPARC).** Three chipset faults found
  with the kernel's own symbols (`mach_kernel` from the CD), pcdump and
  verbose boots, all fixed and on the board:
  - **TMR-8** `ts_timer`: a user timer's RUN bit resets to 1 (QEMU does
    the same). NeXTSTEP switches the CPU counters to user-timer mode,
    never writes Start/Stop, and calibrates its delay loop against the
    count: it hung at "Starting NEXTSTEP".
  - **DEC-4** slot e: an FCode image at +0x1000 names the Sun OBP's DBRI
    node `dbri-absent` (`tools/fcode_cs4231.py`, `ts_decode`, `ts_io`).
    NeXTSTEP's `sbus_config` faulted on the unnamed node.
  - **ESP-7** `ts_esp`: a select's interrupt (line and STATUS INT) is held
    until 1 ms after the command. NeXTSTEP's SCSI driver deadlocked when a
    command completed inside `[NXConditionLock lockWhen:]` (interlock
    held, thread not yet asleep). Two wrong turns on the way: holding the
    selection itself broke OpenBIOS's disk probe (it starts its next
    command without waiting for ICCS's interrupt; `scsitest` mode 2 now
    reproduces that), and 100 us still deadlocked a screen-console boot.
    The 1 ms costs nothing measurable (Solaris 149.2 s to login, CD boots
    109 s / 90 s).

## Gotchas learned this session

- **`pkill -f`/`pgrep -f` match their own shell** (third time): a pattern
  that appears in the command line kills the command itself. Kill by PID.
- **NeXTSTEP's console decides its devices:** serial console (stdin =
  stdout) → no mouse, no keyboard in the GUI. The network panel ("No
  response from network configuration server") is on the screen; Ctrl-C
  on the console skips it (ttya or the keyboard).
- **Every run that reloads the core under NeXTSTEP leaves its root
  unclean:** the next boot fscks and reboots once ("Root fixed"),
  `nextstep.sh` allows for it.
- **Tools for NeXTSTEP work:** `scratch/ns/` (gitignored) has the kernel,
  its symbols (`syms.txt`), a disassembly (`kernel.s`), `kdis.py` (by
  symbol), `xref.py` (who forms an address), `bdis.py` (BuildDisk, no
  symbols); `tools/ufsread.py --offset 0x28000` reads the CD's UFS.
  Kernel helpers: `_setcpudelay`, `_consconfig`, `_sunmouse_init`,
  `_esp_*`, NXConditionLock at 0xf00c93d8/0xf00c9440.
- **A detached `nohup … &` from the Bash tool does not survive;** run long
  jobs with the tool's background mode.
- **Quartus reads the sources at map time:** swapping an RTL file for a
  simulation is safe once "Analysis & Synthesis was successful" is in the
  build log, and must be undone before committing.
