## What exists and how it was proven

### Chipset blocks (plan phase 5, done early) — `rtl/obio/`
`slavio_timer`, `slavio_intctl`, `slavio_misc`, `m48t08`, `escc`/`escc_chan`,
on the I/O bus of [arch/bus.md](../arch/bus.md); packages in `rtl/pkg/`,
`ram_tdp_be` in `rtl/lib/`. Each has a bench in `rtl/obio/tb/`;
`rtl/tb/run.sh` lints everything (`verilator -Wall`, clean) and runs them
all (timer 120, intctl 82, m48t08 34, escc 114, misc 27 checks).
Quartus 17 syntax is checked with `scripts/qcheck.sh` (half a minute on
misterubuntu); it caught three forms Verilator accepts and Quartus 17
rejects (genvar declared in the `for`, declarations in unnamed blocks, two
package imports in a module header) — the sources are fixed, keep to
`genvar n; generate for (n = ...) ... endgenerate`, named blocks, one
header import.

### Proven on the board: the hybrid
The old core with `slavio_timer` + `slavio_intctl` swapped in behind VHDL
shims on its PVC bus (old repo, branch `hybrid`: `rtl/hybrid/*.vhd`,
`*_pvc.sv`, `rtl/new/` verbatim copies, `files.qip` edited). Built on
misterubuntu (`build_hybrid.out`: 79 % ALMs, worst slack −0.04 ns on the
HDMI PLL only), deployed with the NEW repo's `scripts/deploy.sh 20 --rbf
<hybrid rbf> --rom <boot0.rom> --no-launch` and tested with
`scripts/hwtest.sh 20 cpu|netbsd|solaris|--obp ... post`:
- `cpu`: PASS, identical to the baseline (76/0/2);
- `netbsd`: PASS (login and shell on ttya); `solaris`: PASS;
- `post`: stops at a memory-controller ERROR **identically on the release
  rbf** (the known EMC/SMC limit) — not a regression.
Rule for shims (agreed with the user): they read only the old bus package
and port lists; the new blocks are never edited in the old tree; a
difference found on the board is fixed in the new repo from the spec.
Next swaps in order: `m48t08` (+ `nvram_sd` port), then `escc`.

### The integer unit (plan phase 1) — `rtl/cpu/`
`iu.sv` (the 5-stage pipeline of [arch/cpu.md](../arch/cpu.md) §1),
`iu_decode`, `iu_regfile` (8 windows, 4 read ports), `iu_alu`,
`iu_muldiv`; benches in `rtl/cpu/tb/` (ALU 116k vectors against a
reference written from V8 Appendix C, mul/div 33k). The facts are in
[arch/iu-notes.md](../arch/iu-notes.md) (a 1,476-line digest).
`sim/iu/run.sh` builds the suite's integer subset
(`tests/cpu/src/main_iu.S`), the QEMU reference
(`tests/cpu/expected/ss20-iu-qemu.log`), runs the IU with a behavioural
memory and the `escc` on ttya, and compares: **31 PASS, 2 SKIP** (the FPU
checks of `t_iu2`), QEMU's deviations corrected. ~50 s wall. Debug views
on the binary: `+trace` (every commit), `+dmem` (every data access),
`+from=N +to=N` (pipeline state per cycle).
Bugs found and fixed on the way (worth knowing when touching the pipe):
forwarding lost while the consumer waits in E; the register read issued
with the old CWP one cycle before a window change commits; annul/redirect
applied to the instruction after the slot when the slot leaves D the same
cycle; the delay slot of the second DCTI of a jmpl/rett couple is at its
npc, not pc+4; a redirect racing a fetch issued in the same cycle;
sub-doubleword store data must be right-aligned in `wdata[31:0]`.

## Open items and evidence
- IU: `brktest` (interrupt path) and the watchdog reset (IU-1) not done;
  no timing estimate yet (qcheck is syntax only; a trial fit is next).
- `wdtest` reads ASI 4 VA 0xB00, the old core's private SFSR alias; the
  Viking equivalent is 0x1300 (iu-notes.md) — decide with Dan whether the
  test or the core adapts.
- iu-notes.md: the README's "sdiv negative divisor" QEMU deviation is
  stale for QEMU 11 (only the 8.2.2 logs show it); the real SuperSPARC's
  divide only takes 52-bit dividends (traps beyond) — the suite's vectors
  go further, so the core follows V8, not the chip.
- Phase 0 (`emu` top, `sim_top`, `files.qip`/`.qsf`) is not started: the
  new core cannot be built as an rbf yet; board work goes through the
  hybrid.
- The interconnect ([arch/bus.md](../arch/bus.md) "to define") must be
  written before phase 3's caches connect.

## Phase 2, the FPU (2026-10-09, late): done to the suite

Written: `rtl/pkg/fpu_pkg.sv` (FSR fields, opf codes, the unpacked and
wide formats, the IU-FPU interface `fpu_req_t`/`fpu_rsp_t`),
`rtl/cpu/fp_unpack.sv`, `fp_round.sv` (tininess after rounding, as the
SuperSPARC and QEMU; UF on tiny-and-inexact or tiny-with-TEM.UF),
`fp_divsqrt.sv` (restoring divide, 57 steps after the a>=b bit; restoring
square root, 58 steps), `fpu.sv` (16 register pairs, FSR, one-entry FQ,
fp_execute/pending/exception states, the datapath: add/sub with a 3-bit
guard and sticky, 53x53 multiply registered twice, div/sqrt iterative,
compares, conversions, V8 App. N NaN rules). Reference: `tests/fpu/`
(an exact IEEE 754 Python model `fpref.py` with the SPARC conventions
documented in its README, 617k vectors in `vectors/`, regenerable).
**`rtl/tb/run.sh tb_fpu` → PASS, 602,375 checks** (every op, both
precisions, all rounding modes, plus the trap/FQ/sequence-error state
machine). Bugs found by the vectors and fixed: the divider lost the top
quotient bit when a >= b (every 1/1 came out inexact); F?TOi treated
exactly -2^31 as out of range; the square root took rs1 instead of rs2
(the bench now keeps rs1 and rs2 in different registers).

IU integration (`rtl/cpu/iu.sv`, docs/arch/cpu.md §1.7): FP instructions
go one at a time (held in D while another is in E/M/W or the FPU is
busy), so the FPU's state is final in E, where the deferred fp_exception,
the sequence errors and FBfcc are decided after the alignment check
(Table 7-1 order); FPop dispatch, FP load writes, ldfsr and stdfq pop at
W commit; FP store data from the FPU in E; `fpu_req_o.trap_taken` tells
the FPU a trap was taken (pending → fp_exception, otherwise ftt ← 4).
One integration bug: the decoder kept `wr_rd` from the integer load with
the same low op3 nibble, so `ld [..], %f14` also wrote `%sp` — the
unexplained "unexpected trap tt=0 pc=0" and the t_iu2 regression.
**`sim/iu/run.sh` → "result lines match QEMU with its deviations
corrected (39 PASS, 0 SKIP)"**: all eight `t_fpu` tests and both `t_iu2`
FPU checks pass; the QEMU reference includes them.

Still to do for phase 2: `scripts/qcheck.sh` on misterubuntu for the new
files (Quartus 17 syntax; the 53×53 multiply and the 58-bit shifters are
the timing suspects — a trial fit will say), and later a pipelined FPU if
FP throughput matters (the interface rules stay).

## Phase 3, SRMMU and caches (2026-10-09/10): written, first runs

Digest: `docs/arch/mmu-notes.md` (1,590 lines, delegated, checked against
page images of the Viking manual). Design: `docs/arch/mmu.md` (§0 is the
decision table: real SuperSPARC cache geometries so the diagnostic image
is the PROM's; write-through + snoop invalidation; 64-entry TLB with the
ASI 6 image; V8 bus-error traps 0x21/0x29 as the suite expects; probes
always walk; no L2 TLB yet). The interconnect is defined in
`docs/arch/bus.md` / `rtl/pkg/mem_pkg.sv` (36-bit PA, 64-bit data, single
beats and 32-byte bursts, lock, a snoop broadcast of every write).

RTL (all `verilator -Wall` clean, not yet through Quartus):
- `rtl/pkg/mmu_pkg.sv` (AT/FT codes, MCNTL bits, the TLB entry as the
  ASI 6 image, the V8 §H.5 permission table, `cacheable_pa`);
- `rtl/cpu/srmmu.sv`: ASI 4 registers (0x000-0x700, 0x1000, the 0x1300/
  0x1400 aliases, **0xD00 = SYSCONF** — the suite's "is this the core"
  word, RAM MB in 31:20, CPUs in 3:0), 64-entry TLB with two lookup ports,
  the walker (shared, data side first), R/M write-back, V8 fault classes
  and OW rules, probe/flush, ASI 5/6/7;
- `rtl/cpu/l1cache.sv` (ICACHE parameter: 5×64×64 B with half-line valid
  bits / 4×128×32 B), `rtl/lib/ram_tdp64_be.sv`;
- `rtl/cpu/cpu_module.sv`: IU + FPU + SRMMU + caches, the instruction and
  data sides, the ASI decode (docs/arch/mmu.md §4), a walker > data >
  instruction arbiter with the locked-pair rule, ASI 0x38/0x49-0x4C
  registers, the watchdog (error mode → IU reset, BM, SFSR.EM,
  `wd_reset_o`).
- `sim/cpu/`: `cpu_sim.sv` (behavioural interconnect: RAM, PROM, ESCC
  through an I/O-bus bridge, empty-slot bus errors, snoop of every write,
  `+lat`/`+gaps`/`+trace`/`+dmem`/`+mem`/`+cycles`), `run.sh` (builds
  `tests/cpu/src/main_cpu.S` = main.S minus chipset/MSI/SMP, the QEMU
  reference `expected/ss20-cpu-qemu.log`, and a comparison that demands no
  FAIL and no SKIP where QEMU passes, letting the core beat QEMU's
  deviations).

Found so far with the harness (2026-10-10): the IU runs the PROM in boot
mode from the first cycle; uncached fetches cost ~8 cycles each (IE off:
the suite runs with the caches off except in the MMU tests), so the whole
suite needs hundreds of millions of cycles (~5 min of Verilator). Fixed on
the way: two harness bugs (a phantom beat after each ack; the I/O-bus
bridge gave the ESCC a word address — it decodes addr[2:1]); the walker
dropped its memory request after one cycle, so the arbiter released the
port and the ack reached nobody (the first MMU-on fetch hung); the suite's
`mmu_off` clears tags with word stores to ASI 0x0C/0x0E, which the data
side only took as doublewords (now a word writes its half, the other half
0); the walk's owner was not held through the done cycle (a faulting walk
looped forever); a read of the SFSR returned the cleared value (the
register read data is now captured at the ack edge); the walker's R/M
write-back left a stale PTE line in the D-cache (the module invalidates
the line itself: the D-cache ignores its own module's snoops).
Run after the walk-owner fix: **58 PASS, 5 FAIL** (the SFSR reads, the
two L2-TLB tests, t_cache_force's cached PTE), then the buserr tests did
not finish in the budget.

Tests changed (tell Dan): `t_mmu_l2_asi6` and `t_mmu_l2_enable` assumed
the old core's 4-entry D-TLB apart from the ASI 6 image (writing entry 0's
SEL2, evicting with 8 pages). With the TLB being the 64-entry image they
now clear the SEL2 of the entry whose SEL0 holds the page (`L2_DROP_ENTRY`)
and evict with 71 translations.

Quartus 17 (`scripts/qcheck.sh` on misterubuntu, delegated): **the whole
CPU module passes analysis & elaboration** at commit 0039267. Two forms
had to change on the way: an assignment pattern with a named member in
`iu.sv`, and a true dual-port byte-enabled RAM with one write port tied
off ("multiple constant drivers") — the caches now use
`rtl/lib/ram_2r1w_be.sv` (one write port, two read ports).
